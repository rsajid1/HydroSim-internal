# Team Working Agreement

## Project

HydroSim – Interactive Hydroponics & Greenhouse Simulator

---

## Team Expectations

- Be respectful and professional with each other.
- Communicate clearly and early if there are issues or delays.
- Contribute fairly to assigned tasks.
- Ask for help when blocked instead of disappearing.
- Keep the repo and documentation organized.

---

## Communication

- Main communication platform: Discord / WhatsApp / Teams
- Important decisions should be written in the group chat or GitHub.
- Team members should try to respond within 24 hours.

---

## Meetings

- Weekly meetings are held on **Fridays** at 2L30 PM via **Microsoft Teams** or in person.
- Meeting time is determined based on team member availability each week.
- Attend scheduled meetings whenever possible.
- If unable to attend, notify the group ahead of time.
- Meetings should stay focused and productive.

---

## GitHub & Coding Rules

- Push clean and working code whenever possible.
- Use meaningful commit messages.
- Do not directly overwrite another member's work without discussion.
- Pull before pushing to avoid merge conflicts.
- Test features before merging into the main branch.

Example commit messages:

- `Added greenhouse temperature controls`
- `Fixed planter UI bug`
- `Updated crop growth simulation`

---

## Task Management

- Tasks will be divided based on workload and skillset.
- Everyone is responsible for completing their assigned work on time.
- If a task becomes too difficult or delayed, communicate it early.

---

## Conflict Resolution

If disagreements happen:

1. Discuss the issue respectfully as a team.
2. Try to reach a fair solution together.
3. If needed, involve the project manager or instructor/sponsor.

---

## Missed Work

- Repeated lack of communication or contribution may be documented.
- Team members are expected to support the project consistently.

---

## Accountability

If a team member repeatedly misses meetings, fails to contribute, or does not respond to teammates:

1. The issue will be raised with the team respectfully.
2. The member will be asked to follow a focused plan for improvement.
3. If the behaviour continues, concerns will be reported to the professor.

---

## Quality Standards

The team will aim to:

- Write readable and maintainable code.
- Keep documentation updated.
- Follow project requirements and scope.

---

## Pull Requests

- All major changes should be made on a separate branch.
- Pull requests should be reviewed by at least one team member before merging.
- Direct pushes to the main branch are not allowed.
- The main branch should only contain stable code.

---

## Branch Naming

Use clear branch names such as:

- `feature/plant-selection`
- `bugfix/dashboard-error`
- `docs/update-readme`

---

## Testing Requirements

- Features must be tested before a pull request is submitted.
- The level of testing required is at the reviewer's discretion based on the scope of the change.
- The team member reviewing the pull request is responsible for verifying that the feature works as expected before approving.

---

## Definition of Done

A task is complete when:

- The code works as expected.
- The feature has been tested.
- Related documentation is updated.
- The code has been pushed and reviewed.

---

## Agreement

By contributing to this repository, team members agree to follow this working agreement and support the success of the HydroSim project.
